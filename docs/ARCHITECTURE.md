# Architecture of release 2

## Two kinds of code in this repository

| Where | What | May it be edited? |
|---|---|---|
| `pipeline/`, `analyses/`, `protocol/`, `manuscript_tools/` | The registered research releases (1.5.3 to 1.5.6), the analysis scripts of amendments A4 to A19 and the protocol. Every published number comes from these files, and their SHA-256 hashes are recorded in the protocol. | **No.** They are the record. A change of one character breaks the chain between the protocol and the results. |
| `src/arf/`, `tests/unit/`, `tests/parity/`, `tools/` | Release 2: the same method as a documented, typed, tested Python package. | Yes, under the rule below. |

## The rule for release 2

**A module is added only together with a test showing that it reproduces the registered release exactly.**
Release 2 changes how the code is organised and named. It does not change what is computed. Where the registered
release makes a choice that a reader might question (how ties are broken, how a repeated cell is counted, a bisection
that assumes monotonicity), release 2 makes the same choice and says so in the docstring.

## Checking release 2 on real runs

```
python tools/check_selection_on_runs.py --index ARF_batch/paper2_v156_a18_core_index.csv
python tools/check_cloud_on_runs.py --index ARF_batch/paper2_v156_a18_core_index.csv
python tools/check_failsignal_on_runs.py --index ARF_batch/paper2_v156_a18_core_index.csv --seeds 3
python tools/check_grid_on_runs.py --boundaries ARF_boundaries --index ARF_batch/paper2_v156_a18_core_index.csv
python tools/check_fleet_on_runs.py --index ARF_batch/paper2_v156_a18_core_index.csv
python tools/check_access_on_runs.py --index ARF_batch/paper2_v156_a18_core_index.csv --max-satellites 250
```

The first compares release 2 with `arf_onset_robustness.csv` of every finished run, onset by onset. The second rebuilds
the cloud mask of each of a run's cloud realisations and compares its cloudy share with `arf_cloud_robustness.csv`. The third recomputes, per realisation, the images and coverage of the Fail-Signal selector and of
the plans it is compared with. The fourth discretises each run's region again from the WDPA downloads and compares the cells and the site
reports with those the run recorded; it prints counts only. The fifth selects each run's fleet again from the element-set files the run recorded and compares
the counts and the satellites; it prints counts only. The sixth propagates each run's fleet again with Orekit, twice: with release 2 and with the registered cells
executed unchanged; the two must be identical, and release 2 is then compared with the run's own tables and
summaries within a tolerance. All exit with status 1 on any difference, read the run folders and write nothing.

## Conventions

* Names say what a thing is in the domain: `floor_min`, `required`, `by_delivery`. Units go in the name (`_min`, `_h`, `_km`, `_percent`).
* Public functions and classes have Google-style docstrings and type hints. One module, one responsibility.
* No global state. A function's result depends on its arguments only; randomness takes an explicit seed.
* `ruff check` and `ruff format --check` pass with the rules in `pyproject.toml`.
